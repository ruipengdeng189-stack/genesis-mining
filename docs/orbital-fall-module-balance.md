# Orbital Fall 模块与玩法设计

## 1. 产品定位

- `Game 8` 定位为 `orbital-fall`
- 中文名：`轨道坠落`
- 英文名：`Orbital Fall`
- 类型：`单手生存射击 + 轻肉鸽 Build + 章节闯关 + 局外成长 + 赛季 / 商店`
- 目标：补足前 7 个游戏里“战斗页独立、短局高频、单手强操作感”的空位

### 它和前面 7 个游戏的关系

- `mining` 承担长线资源主线
- `runner` 承担即时反应和短局刺激
- `gem-forge` 承担合成与稀有掉落
- `defense` 承担塔防章节推进
- `drone-squad` 承担战斗编队成长
- `neon-cards` 承担轻策略对抗
- `cipher-match` 承担休闲留存与日常任务
- `orbital-fall` 负责提供：`更强的战斗主场感 + 6 分钟内短局循环 + 单手竖屏 APP 化体验`

## 2. 核心体验目标

- `5 秒内` 让玩家看懂：这是一个“拖动走位、自动开火”的竖屏生存战斗游戏
- `20 秒内` 让玩家看到第一次升级选择、第一次危险压迫、第一次技能释放
- `3 分钟内` 形成“再来一局 / 先补一笔成长再回来”的短循环
- `1~3 天内` 让免费玩家能稳定推进，同时让付费玩家明显缩短中期养成时间

## 3. 核心玩法循环

1. 在 `Run` 页选章节与关卡
2. 确认本次出战配置：`1 机体 + 2 主武器 + 1 无人机 + 1 大招`
3. 进入独立战斗场景，玩家单指拖动走位，武器自动开火
4. 击败敌群、精英与 Boss，拾取经验球与掉落资源
5. 升级时进行 `3 选 1` 临时强化
6. 结算获得 `Credits / Alloy / Signal / Season XP`
7. 回到 `Arsenal` 升级机体、武器、无人机、大招
8. 回到 `Lab` 进行永久研究
9. 通过 `Missions / Season / Shop / Payment` 补齐成长缺口后继续推进

## 4. 战斗页必须独立

`Orbital Fall` 的核心不是“在 Run 页里放一个小战斗窗口”，而是让战斗本身成为单独场景。

### 4.1 进入战斗前

- `Run` 页只负责准备，不负责承载全部信息
- 准备页只保留四个核心块：
  - `章节`
  - `当前战力`
  - `本次出战配置`
  - `开始按钮`

### 4.2 战斗进行时

- 隐藏大厅页签与大段说明
- 不展示研究树、商店推荐、赛季长文案
- HUD 只保留：
  - 顶部：`血量 / 护盾 / 剩余时间 / 大招充能`
  - 中部：`短提示 / 升级三选一 / Boss 预警`
  - 底部：`大招键 + 暂停键`
- 战斗失败 / 胜利后再回到结算层，不把局外复杂信息压在战斗同屏

### 4.3 暂停页逻辑

- 只允许：
  - `继续`
  - `退出结算`
- 不要在暂停层再塞进装备详情、研究面板、付费弹窗

## 5. APP 适配逻辑

## 5.1 单屏原则

- 玩家进入 `Run`，默认一屏就能看到开打入口
- 玩家进入 `Live Battle`，默认一屏就能看到完整战斗区域
- 玩家进入 `Arsenal / Lab / Missions / Season / Shop`，都应控制为单屏主视图 + 内部滚动

## 5.2 文案压缩原则

- 优先图标、短标签、数字
- 说明文案只在：
  - 首次教学
  - 长按 / 点开详情
  - 暂停页 / 结算页
- 常驻文本不超过 `1~2 行`

## 5.3 战斗页屏幕分层

- 顶部 `10~14%`：紧凑 HUD
- 中部 `70%+`：主战斗区
- 底部 `12~16%`：技能 / 暂停操作
- 安全区优先兼容刘海屏与底部手势区

## 5.4 各页职责拆分

### `Run`

- 只放：章节、推荐战力、当前出战、开始
- 不放长任务描述、不放商店推荐、不放研究详情

### `Arsenal`

- 只放装备与升级
- 每张卡片默认显示：
  - 图标
  - 名称
  - 当前等级
  - 战力贡献
  - 升级按钮

### `Lab`

- 只放永久研究
- 强调“当前收益 + 下一层提升”

### `Missions`

- 只放任务进度与领取
- 不放成长解说

### `Season`

- 只放赛季轨道、奖励、通行证入口

### `Shop`

- 分为：
  - `免费 / 软货币`
  - `礼包 / 支付`
- 每个礼包只展示：
  - 价格
  - 核心奖励
  - 一条永久收益标签

## 6. 战斗节奏设计

### 6.1 单局时长

- 普通关：`120~180 秒`
- 精英关：`150~210 秒`
- Boss 关：`210~300 秒`

### 6.2 节奏结构

- `0~40 秒`：热身，快速进入第 1 次升级
- `40~90 秒`：敌群密度上来，逼迫玩家开始拉扯走位
- `90~150 秒`：精英压迫，检验构筑方向
- 最后 `30~60 秒`：Boss 或最终目标处理

### 6.3 单局内的成长表达

- 玩家每局至少看到 `3~5 次` 强化选择
- 前 2 次升级更偏稳定收益：
  - 射速
  - 子弹数量
  - 护盾恢复
  - 拾取范围
- 后续升级逐步开放构筑型收益：
  - 暴击扩散
  - 大招充能
  - 无人机超频
  - 近身爆发

## 7. 模块清单

## 7.1 机体 `Hull`

- 决定生存容错和基础移动手感
- 初版 3 台：
  - `flare`：均衡新手
  - `bulwark`：厚盾容错
  - `vector`：高速闪避

## 7.2 武器 `Weapons`

- 决定清群、穿透、追踪、控场、对 Boss 输出
- 初版 8 把
- 前期优先给玩家“稳定清群”和“自动追踪”两种明确选择

## 7.3 无人机 `Drones`

- 负责拾取、护盾、治疗、Boss 伤害、控场、充能辅助
- 初版 6 台

## 7.4 大招 `Ultimates`

- 每次释放都必须有清晰强反馈
- 初版 4 个方向：
  - 清屏
  - 位移脱险
  - 聚怪控场
  - 首领爆发

## 7.5 永久研究 `Lab`

- `Thruster Mesh`：基础战力
- `Salvage Link`：金币收益
- `Alloy Press`：合金收益
- `Signal Tuner`：研究减负
- `Elite Protocol`：精英收益
- `Core Reactor`：大招充能

## 8. 成长压力点的设计原则

这里的“压力点”只用于内部数值设计与付费映射，不直接暴露给用户文案。

- `1-4 / 1-6`：第一次战斗密度与 Boss 检验
- `2-3`：第一次双资源压力
- `3-3`：第一次完整构筑检验
- `4-2 / 4-4`：后期多系统同步成长检验

设计目标不是“卡住玩家”，而是让：

- 免费玩家可以靠日常活跃继续推进
- 小付费玩家可以更快补齐中期缺口
- 中付费玩家获得更顺滑的终盘成长

## 9. 付费设计原则

- 付费价值不应是“直接跳过全部内容”
- 付费应该主要解决：
  - 成型时间
  - 多线资源压力
  - 终盘容错不足
- 对用户可见描述使用：
  - `成长更顺`
  - `收益更稳`
  - `更适合当前进度`
- 不使用：
  - `卡点`
  - `逼氪`
  - `必须购买`

## 10. 当前设计结论

`Orbital Fall` 适合作为 `Game 8` 的原因已经明确：

- 它能提供与前 7 个游戏差异明显的战斗主体验
- 它适合做强 APP 化单手竖屏战斗
- 它非常适合“短局高频 + 局外成长 + 赛季 + 支付映射”
- 它的战斗页天然应该做成独立场景，而不是普通页签中的一个子模块

下一步若继续实现，建议优先顺序：

1. `games/orbital-fall/index.html`
2. `games/orbital-fall/orbital-fall.css`
3. `games/orbital-fall/orbital-fall.js`
4. 将 `orbital-fall.config.js` 反推到真实运行时参数
